# File Sync Service

Учебный сервис зеркалирования локальной папки в Яндекс Диск. Сравнивает вложенные файлы и папки, создаёт отсутствующие объекты в облаке, загружает новые и обновляет изменённые файлы по времени модификации.

## Поведение

- Локальная папка служит источником истины; облачные объекты, отсутствующие локально, удаляются.
- Цикл повторяется с настраиваемым интервалом.
- Сетевые запросы используют timeout; ошибки конфигурации, сети, API и файловых операций обрабатываются собственными исключениями и записываются в журнал.
- После ошибки в основном цикле следующая попытка выполняется с обычным интервалом.

**Удаление в облаке выполняется с permanently=true, без помещения объекта в Корзину Яндекс Диска.** Используйте отдельную демонстрационную папку и резервную копию. Не направляйте сервис на облачную папку с единственными экземплярами нужных файлов.

**Стек:** Python 3.8+, Requests, python-dotenv, Loguru, Яндекс Диск API.

## Запуск

Из каталога python-portfolio:

```sh
cd file-sync-service
python -m venv .venv
```

В PowerShell: `.\.venv\Scripts\Activate.ps1`. В Linux/macOS: `source .venv/bin/activate`.

```sh
pip install -r requirements.txt
cp .env.example .env
```

В PowerShell вместо cp: `Copy-Item .env.example .env`. Заполните настройки из шаблона, включая OAuth-токен Яндекс Диска, локальную и облачную папку. Токен получают в инструментах Яндекс Диска для своего аккаунта; реальный токен в Git не добавляется.

```sh
python main.py
```

Остановка — Ctrl+C. Перед запуском проверьте обе папки: сервис выполняет реальные загрузки и удаления через API.

## Архитектура

- main.py — запуск приложения.
- app.py — загрузка конфигурации и основной цикл.
- sync_service.py — сравнение списков и операции синхронизации.
- file_manager.py — чтение локальной файловой системы.
- yandex_disk.py — HTTP-клиент облачного API.
- config.py, exceptions.py, ui.py — настройки, исключения и журналирование.

## Статус и ограничения

Учебная реализация. Нет отдельного набора автоматических тестов и CI, режима dry-run и проверки содержимого файлов по хешам. Сравнение основано на mtime; локальные пропуски при чтении могут повлиять на итоговый список. В проекте нет механизма восстановления облачных удалений. Токен загружается из .env; файл добавлен в .gitignore, этот файл не является шифрованным хранилищем. Работа с реальным Яндекс Диском при этой редактуре не запускалась.
